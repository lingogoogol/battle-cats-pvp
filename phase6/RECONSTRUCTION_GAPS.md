# 《貓咪大戰爭》全專案重建落差稽核 (RECONSTRUCTION_GAPS.md)

本文件依照「**禁止宣稱完成整個遊戲的還原，所有未完成部分均列入 GAPS**」原則，詳列目前專案由「逆向研究」過渡至「完整可執行遊戲」之間的真實技術斷層：

---

## 一、 核心代碼層級落差 (Code Level Gaps)

| 落差項目 | 現有成果 | 未完成部分與技術障礙 | 嚴重程度 |
| :--- | :--- | :--- | :--- |
| **原生 C++ 核心引擎** | 定位 58 個 JNI 介面、主迴圈與封包註冊表；建立 Capstone 反組譯映射 | 11.55 MB 之二進位內部數萬個私有函式、物理碰撞、傷害公式細部實作缺乏除錯符號，無法還原為原始 C++ 專案 | **【致命 (Critical)】** |
| **Java 原始碼直編性** | 99.5% 類別反編譯為 Java 檔案；Ponos 原廠 Activity 與回調完整 | 76 個混淆類別具有 JADX 錯誤標記；大量單字母符號衝突，無法在未重構狀態下直接通過 `javac` 編譯 | **【高 (High)】** |
| **戰鬥邏輯完整性** | 建立核心戰鬥原型 (`prototype/battle_engine.py`) 並通過 8 項單元測試 | 原版特殊機制（如：波動攻擊、擊退硬直幀、暫停動作、爆擊率、寶物疊加公式）尚未全數逆向移植 | **【中 (Medium)】** |

---

## 二、 資產與資料層級落差 (Asset & Data Gaps)

| 落差項目 | 現有成果 | 未完成部分與技術障礙 | 嚴重程度 |
| :--- | :--- | :--- | :--- |
| **核心數值封包 (`.pack`)** | 完整提取 8 組 `.pack` 與 `.list` 二進位檔案；證實採用 AES-128-ECB 模式 | 尚未提取出執行時金鑰或透過 Frida Hook 輸出記憶體明文，封包內部的數百個關卡與怪物 CSV 仍為密文 | **【致命 (Critical)】** |
| **骨架動作與模型** | 提取 `ImageDataLocal.pack` 與未加密圖片 | 貓咪與敵人由專有骨架格式（mamodel / maanim）驅動，其動畫解析器包覆於 C++ 內部，尚未提取為通用 Spine/Live2D 格式 | **【高 (High)】** |

## 三、 系統與伺服器邊界落差 (System & Server Gaps)

| 落差項目 | 現有成果 | 未完成部分與技術障礙 | 嚴重程度 |
| :--- | :--- | :--- | :--- |
| **本機動態測試驗證** | Apktool 成功重組 33.07 MB APK；確認 ABI 與 SDK 門檻 | 本機無 ADB 工具與 ARM64 模擬環境，實機安裝、啟動、選單與戰鬥測試全數處於 **BLOCKED** 狀態 | **【高 (High)】** |
| **伺服器端業務邏輯** | 逆向確認 `libsigner.so` 簽名與 HTTP 回呼介面 | 存檔認證、轉蛋隨機數、體力回覆等核心資料由 Ponos 遠端伺服器控制，非客戶端本地程式碼所能還原 | **【不可逆 (Unresolvable)】** |

---

## 四、 總結判定

當前進度已完成**架構解構、JNI 拓撲測繪、資產載入鏈證明與等價戰鬥引擎原型開發**；但距離「可編譯、可發布的完整原始商業遊戲專案」，仍存在上述不可迴避的客觀工程落差。
