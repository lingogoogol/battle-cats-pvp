# 《貓咪大戰爭》逆向工程落差與技術限制分析 (GAPS.md)

本文件以最嚴格之工程誠信標準，逐項揭露目前逆向工程中**尚未恢復、無法還原或受限於二進位物理特性**的具體環節：

---

## 一、 原生 C++ 原始碼的不可逆落差 (Native Code Gap)

1. **除錯符號與函式識別遺失**：
   `libnative-lib.so` 在發布前已被全面剥除符號（Stripped）。除了 JNI 規範強制保留的 58 個導出函式外，內部估計數萬個內部 C++ 類別、私有方法、內聯函式（Inlined Functions）皆失去原始名稱，僅剩十六進位記憶體位址（如 `0x00450dc8`）。
2. **巨集與型態結構消除**：
   C++ 編譯器優化（O2/O3、向量化、暫存器配置）已將高階抽象語法瓦解為 ARM64 組合語言。逆向工具產生的「反編譯 C 偽代碼」是指令模擬的猜測結果，**不可能 100% 還原出原廠專案的 `.cpp` 與 `.h` 檔案**。

---

## 二、 核心遊戲資產的加密封鎖 (Encrypted Asset Gap)

1. **未解密封包現況**：
   遊戲的核心關卡設定、貓咪體質與攻擊力、寶物倍率、轉蛋機率表皆封裝於 `DataLocal.pack` 與 `UnitLocal.pack` 等 8 個二進位封包內。
2. **落差定義**：
   雖然檔案已自 APK 中成功抽出，但其本質為 **AES-128-ECB 加密區塊**。在未調用/模擬 `libnative-lib.so` 的解密子常式產出明文 CSV/TSV 之前，**不可宣稱遊戲數值庫已成功還原**。

---

## 三、 Java / Kotlin 程式碼之語法與架構落差 (Java Semantics Gap)

1. **反編譯死角 (76 個類別失效)**：
   JADX 在處理控制流扁平化（Control Flow Flattening）與複雜例外處理時，共有 76 個類別出現硬性反編譯中斷（產生 `JadxOverflowException` 或跳過方法體），這些代碼目前無法直接編譯。
2. **混淆代名詞（a/b/c）**：
   ProGuard / R8 剥除了區域變數名、參數名與私有成員名，若要恢復為具可讀性的專案，需耗費大量人工進行符號重構（De-obfuscation）。

---

## 四、 伺服器動態協定與防作弊簽章 (Network & Anti-Cheat Gap)

1. **`libsigner.so` 封閉簽名算法**：
   遊戲客戶端向 Ponos 伺服器發送的請求皆經過 `libsigner.so` 進行雜湊簽章，以防止重放攻擊與外掛竄改。此演算流程包含動態 Salt 與專有混淆，純靜態分析無法直接得出完整的通訊偽造能力。
2. **伺服器端驗證邏輯 (Server-Side Logic)**：
   存檔同步、抽卡判定、活動排程等關鍵邏輯位於 Ponos 遠端伺服器，**不在 APK 本地程式碼之中**，任何客戶端逆向皆無法取得伺服器端後台源碼。

---

## 五、 落差改善路徑建議

| 尚未還原項目 | 阻礙難題 | 建議之後續突破手段 |
| :--- | :--- | :--- |
| **`.pack` 內部明文資料** | AES 金鑰與解包常式 | 使用 Frida Hook 攔截 `AAssetManager_read` 解密後的記憶體緩衝區 |
| **Java 編譯中斷** | 76 個混淆類別語法錯誤 | 以原始 Smali 為基底手動修補，或用標準開源庫取代該 SDK |
| **原生邏輯功能等價重寫** | 百萬行 ARM64 彙編 | 針對 58 個 JNI 介面撰寫現代 C++ 封裝，實現開源版引擎實例 |
